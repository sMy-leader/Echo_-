# ECHO / 残响 — 核心规则 v0.1

> 这些规则直接决定代码结构。改动规则前先改本文件，再改实现。

## 1. 时间模型

| 规则 | 值 / 决策 |
|---|---|
| 逻辑 tick | 60Hz（`1/60s`） |
| 渲染 | 不限制，插值显示 |
| 回溯目标 | 最近检查点快照 |
| 回溯演出 | 0.6s（M0 先用简单 fade + 相机震动占位） |
| 回溯冷却 | 0.5s |
| 回溯后无敌 | 0.3s |
| 手动重开 | 长按 R 1s，清空残影并回到关卡起点 |
| 单轮录制上限 | 30s（1800 帧） |

## 2. 残影规则（已拍板）

1. **回溯时所有残影统一回到 t=0。**
   本体、旧残影、新残影都从检查点时间轴重新开始，避免时间错位。
2. **残影死亡只在当前时间线内有效，下次回溯复活。**
   时间倒流应撤销死亡；这样“挡激光牺牲”仍是策略，但玩家敢试错。
3. **进入新检查点时清空所有残影。**
   旧残影的 t=0 对应旧检查点，跨段保留会导致轨迹错位。
4. **录制到 30s 后停止录制，玩家仍可操作，UI 提示。**
   不自动回溯，避免打断玩家。
5. **残影轨迹结束立即消散，并发出半径 8m 的声音事件。**
   压力板在 0.3s 后重新计算；机关状态不会出现“门开着但没人踩”。

### 残影可交互白名单

| 对象 | 残影可触发 | 备注 |
|---|---|---|
| 压力板 | 是 | M0 只做这个 |
| 拉杆 | 是 | 需要 0.5s 按住 |
| 激光/守卫伤害判定 | 是（会被击杀） | 死亡后消散 |
| 可推动箱子 | 否 | 防止回放分叉 |
| 门把手/需要长按的门 | 否 | 由本体完成 |

### 残影数量

- 上限 3 个，FIFO：第 4 次回溯挤掉最旧的。
- 视觉年龄编码（青→紫）后置到 M1；M0 只用 HUD 槽位数量表达。

## 4. 输入映射

| 动作 | 键鼠 | 手柄 |
|---|---|---|
| 移动 | WASD | 左摇杆 |
| 潜行 | Shift（按住） | LB |
| 交互 | E / 鼠标左键 | A |
| 回溯 | R | B |
| 时间轴 | Tab（按住） | 十字键上 |
| 暂停 | Esc | Start |

`Gameplay` / `UI` / `Debug` 三套 Action Map。逻辑层只接收抽象后的 `InputFrame`。

## 5. 机关规则

- 压力板：有激活源时开启，离开 0.3s 后关闭。
- 机关状态由 `ActivationAggregator` 每 tick 重新计算，不由“谁踩上去”直接改状态。
- 支持 `OR` / `AND` / `COUNT` 三种聚合模式；M0 只实现 `OR`。
- 门/升降台等表现只订阅状态变化，不参与判定。

## 6. 守卫感知与状态机（M1 第一块）

### 6.1 视觉

- 水平视角 60°（半角 30°）、垂直视角 40°（半角 20°）、距离 8m。
- 视觉采样 10Hz（每 0.1s），警戒值仍然每 tick 更新。
- 目标进入 2m 内时按“近身警觉”处理，不再要求目标在视锥中心；解决守卫贴身后反而看不见的边界。
- 视线遮挡由 `Physics.Linecast` 判断；墙、关闭的门会阻挡视线。
- 感知目标包括本体和残影；残影可以被守卫看见。

### 6.2 警戒值

- 范围 0–100。
- 视觉内每秒 +40；脱离视觉每秒 -15。
- 警戒值 ≥60 → `Investigate`。
- 警戒值 ≥100 → `Alert`。

### 6.3 状态

| 状态 | 行为 | 速度 / 时间 |
|---|---|---|
| Patrol | 沿路点巡逻，到达后停留 2s | 1.6 m/s |
| Suspicious | 停下，面向可疑点，警戒值上升 | — |
| Investigate | 走向最后已知位置；到达后转 Search | 2.2 m/s |
| Alert | 追击最后已知位置；进入 2.4m 后 0.4s 扑击 | 3.6 m/s |
| Search | 原地转头搜索；8s 无果转 Return | 90°/s |
| Return | 回到最近巡逻点，然后 Patrol | 1.8 m/s |

### 6.4 M1 当前的边界

- 守卫目前是**直线移动**；L1 布局时再接入胶囊碰撞/寻路，不影响状态机。
- 攻击已接入：Alert 进入 2.4m → 0.4s 蓄力 → 命中本体触发失败回溯；命中残影只击杀残影。
- 失败回溯当前是“立即恢复检查点 + 0.9s HUD 提示 + 相机震动”；0.8s 时间撕裂后处理在 M1.6b 补。
- 还没有听觉；声音事件在 M3 接入。
- 残影已有 `IsAlive` / `TryKill`；死亡后下一 tick 从列表移除。
- 守卫参数先用 `GuardConfig` 纯 C# 默认值；后续由 ScriptableObject/关卡配置注入。

## 7. 失败与重试

| 情况 | 处理 |
|---|---|
| 本体被守卫抓住 | 立即恢复检查点 + 0.9s HUD 提示 + 相机震动；不生成残影（0.8s 时间撕裂后处理 M1.6b） |
| 本体被激光击杀 | 同上 |
| 残影被击杀 | 消散 + 8m 声音，本体不受影响 |
| 卡关 3 分钟 | 右上角出现提示按钮，可关闭 |
| 存档损坏 | 回退 `.bak`，失败则新建（后置） |

## 8. M0 验收规则

- 玩家踩板 → 门开；离开 → 0.3s 后门关。
- 按 R → 本体回检查点 → 残影重演踩板 → 门保持开启 → 本体通过。
- 连续回溯 4 次 → 只保留最近 3 个残影。
- 录制到 30s → 停止录制并提示，玩家仍可移动。
- 进入新检查点 → 残影清空。
